# AGENTS.md

## Проект и источник кода

- Проект: сайт «Простор».
- Основной репозиторий: `PV-develop/prostor-2026` (`https://github.com/PV-develop/prostor-2026`). Основная ветка — `main`.
- GitHub — основной источник кода.
- Во время визуальных итераций работаем преимущественно с локальной копией репозитория.
- Перед началом крупного этапа один раз синхронизируемся с GitHub и проверяем наличие нужных ресурсов локально.
- Не скачиваем повторно уже имеющиеся файлы.
- Не используем GitHub для чтения файлов при каждой операции.
- Не перезаписываем локальные правки без проверки; при расхождении сначала разбираем ситуацию с пользователем.

## Git и публикация

- Не публикуем сайт, не создаём production-релиз и не отправляем изменения в GitHub без явного согласования с пользователем.
- Commit и push выполняем только после утверждения пользователем блока или логической группы правок.
- Не коммитим каждую промежуточную итерацию.
- Перед commit/push убеждаемся, что изменённые страницы проверены на desktop и mobile.

## Технологический стек

- Astro + TypeScript.
- Статическая генерация.
- Без Tailwind и CSS-фреймворков.
- Без headless CMS.
- React не подключаем без отдельного согласования.
- Интерактивность реализуем на чистом TypeScript/JavaScript только там, где она действительно нужна.
- Работающий сайт не должен зависеть от внешних CDN: никаких Google Fonts, Unpkg и других внешних скриптов/шрифтов.

## Текущее состояние проекта

Главная страница перенесена на Astro + TypeScript. Экспорт Claude Design сохранён как визуальный референс в `reference/claude-design/`; эти файлы не участвуют в Astro-сборке и вручную не редактируются.

Актуальный код сайта:

- `src/pages/index.astro` — главная страница.
- `src/components/ui/` — базовые UI-компоненты.
- `src/components/blocks/` — библиотека универсальных блоков.
- `src/components/layouts/` — шаблоны страниц.
- `src/styles/design-tokens.css` — единый источник дизайн-токенов.
- `src/styles/global.css` — базовые стили и общие классы.
- `src/content/home.ts` — контент главной страницы.
- `src/scripts/main.ts` — интерактивность на чистом TypeScript.
- `public/` — локальные шрифты, логотипы и изображения.
- `docs/design-system.md` — документация дизайн-системы.
- `docs/blocks.md` — документация библиотеки блоков.

Команды:

- `npm run dev` — dev-сервер;
- `npm run build` — production-сборка в `dist/`;
- `npm run preview` — просмотр сборки;
- `npx astro check` — проверка типов.

## Дизайн-система

- Используем `src/styles/design-tokens.css` как единый источник цветов, типографики, отступов, сетки, брейкпоинтов и переходов.
- Не хардкодим цвета, отступы, размеры и типографику вне токенов.
- Если значение используется два и более раза — выносим в токен.
- Уникальное значение локального блока можно хранить как токен блока, если оно должно управляться отдельно.
- Существующие блоки переиспользуем.
- Если новый блок на 80% и более похож на существующий, расширяем существующий компонент типизированными props, а не создаём копию.
- Новые универсальные блоки добавляем в `src/components/blocks/` и фиксируем в `docs/blocks.md`.
- Одностраничные локальные блоки можно держать рядом со страницей, если они не предназначены для переиспользования.

## Внутренние страницы

- Каждая внутренняя страница начинается с брифа и контента.
- Перед реализацией должна быть подготовлена спецификация в `docs/page-specs/<slug>.md`.
- Агент реализации читает спецификацию, `docs/blocks.md` и при необходимости `docs/design-system.md`.
- Не читаем всю главную страницу без необходимости; используем документацию библиотеки как карту блоков.
- Для активного пункта меню используем соответствующее состояние текущей страницы.
- Контент, SEO и факты не зашиваем внутрь универсальных компонентов.
- Не выдумываем клиентов, отрасли, цифры, кейсы, сроки, бюджеты и ответы FAQ.
- Если данных нет, явно оставляем TODO и сообщаем об этом пользователю.
- Не добавляем внешние ссылки, iframe, демо и редиректы без отдельного согласования.
- Скриншоты итоговых состояний сохраняем в `screenshots/astro/pages/<slug>/`.

## Контент и SEO

- Кейсы и статьи храним в Markdown.
- Типовые блочные страницы описываем через YAML.
- SEO-параметры храним вместе с соответствующей страницей.
- Редиректы храним отдельно.
- Черновые SEO title/description можно формировать из H1 и первого абзаца, но финальные значения должны быть проверены вручную.

## Запрещено

- Tailwind и CSS-фреймворки.
- Headless CMS.
- Хардкод дизайн-значений вне токенов.
- Внешние шрифты, скрипты и изображения.
- React без отдельного согласования.
- `href="#"` как рабочая ссылка.
- Мёртвые ссылки на несуществующие страницы.
- Копирование одного и того же блока между страницами.
- Ручное редактирование сгенерированного экспорта Claude Design.
- Commit/push без согласования.
- Production-публикация без отдельного явного указания.

## Порядок проверки изменений

1. `npx astro check` без ошибок.
2. `npm run build` без ошибок.
3. Просмотр страницы на 1440px и 375px.
4. Проверка отсутствия горизонтального скролла.
5. Проверка отсутствия 404 у локальных ресурсов.
6. Проверка консоли на ошибки.
7. Проверка затронутой интерактивности: меню, формы, якоря, мобильные состояния.
8. Скриншоты итоговых состояний сохраняются в `screenshots/astro/` или `screenshots/astro/pages/<slug>/`.
